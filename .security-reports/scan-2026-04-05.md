## What Your Code Does RIGHT

> Security strengths found in this codebase. These are good practices to preserve and extend.

### React JSX auto-escaping throughout — all viz components
Every visualization renders data values as JSX text content or SVG attributes (`<text>`, `<title>`, `<td title={…}>`), never via `innerHTML` or `dangerouslySetInnerHTML`. React escapes all interpolated values, eliminating XSS from data rendering.

Confirmed in:
- `src/viz/data-table.tsx:67–68` — column headers rendered as JSX text
- `src/viz/data-table.tsx:80` — `title={String(row[f.key] ?? '')}` → escaped HTML attribute
- `src/viz/force-graph.tsx:138` — `<title>{node.label}</title>` → escaped SVG text
- `src/viz/choropleth.tsx:66` — tooltip rendered as `<title>` text, not innerHTML
- All chart label/tick text rendered as SVG `<text>` elements

### Primitive-only DataRow type — `src/transforms/types.ts:7`
```ts
export type DataRow = Record<string, string | number | boolean | null>;
```
`DataRow` restricts values to safe primitives. This prevents object injection, prototype pollution via value assignment, and accidental function/class smuggling through the data pipeline. Downstream renderers calling `String(val)` or `Number(val)` on a `DataRow` value cannot be surprised by a malicious object.

### No dangerouslySetInnerHTML anywhere
Grep confirmed: zero occurrences of `dangerouslySetInnerHTML`, `innerHTML`, `outerHTML`, or `document.write` across all 35 files. The SVG path data in `Choropleth` (`src/viz/choropleth.tsx:64`) is set as the `d` attribute on a `<path>` element — an SVG geometry attribute that cannot execute scripts.

### No eval() / new Function() / dynamic code execution
Zero occurrences of `eval(`, `new Function(`, `setTimeout(string`, `setInterval(string` across the entire codebase. The `TransformPipeline` executes transforms via standard function calls, not dynamic eval.

### No hardcoded credentials or secrets
Zero matches for hardcoded `password`, `secret`, `api_key`, `token`, or `private_key` patterns. All configuration is passed via props and TypeScript interfaces.

### No network requests
The library makes zero outbound network calls. There are no `fetch(`, `axios`, `XMLHttpRequest`, or `WebSocket` calls. No SSRF surface exists.

### Immutable data flow in transforms — `src/transforms/`
All five transform implementations (`flatten`, `aggregate`, `pivot`, `groupBy`, `geoNormalize`) return new objects rather than mutating their input:
- `flatten.ts:66`: `return { rows, fields: deriveFields(rows) }`
- `aggregate.ts:79`: `return { ...data, rows, fields }`
- `geo-normalize.ts:47`: `return { ...data, geo }`

Immutability prevents one transform from corrupting shared state used by another step in the pipeline.

### No prototype pollution path in flatten — `src/transforms/flatten.ts`
The `flattenObject` function recurses into nested objects and produces dot-separated string keys (e.g. `__proto__.isAdmin`), never directly assigning a key named `__proto__` or `constructor` to the result object. Input keys containing `__proto__` become literal string keys with a separator — they do not reach `Object.prototype`.

### TypeScript strict mode + exactOptionalPropertyTypes — `tsconfig.json`
```json
"strict": true,
"exactOptionalPropertyTypes": true,
"noUncheckedIndexedAccess": true
```
Strict TypeScript with `noUncheckedIndexedAccess` prevents implicit `undefined` index access, reducing a whole class of runtime errors that could manifest as denial-of-service or unexpected behavior when consuming untrusted data shapes.

### D3 adapter lifecycle enforces cleanup — `src/plugins/d3-adapter.tsx:94–102`
```ts
useEffect(() => {
  const el = containerRef.current;
  return () => {
    if (el && mountedRef.current) {
      lifecycle.destroy(el);
      mountedRef.current = false;
    }
  };
}, []);
```
The D3 adapter mandates a `destroy()` lifecycle method and calls it on unmount. This prevents event listener leaks and dangling DOM references that could accumulate across view-switch cycles, which in long-running apps can degrade performance or cause memory-based DoS.

### No server-side code, no authentication surface
VizBox is a pure rendering library. There are no Express/Fastify routes, no session handling, no cookie management, no JWT validation, and no RBAC logic. The OWASP categories A01 (Broken Access Control), A07 (Authentication Failures), and A10 (SSRF) have zero applicable surface area.

## Vulnerabilities Found

### [LOW 3.7] Non-cryptographic Math.random() for visual layout — `src/viz/force-graph.tsx:83–84`
**OWASP**: A02 — Cryptographic Failures (informational / context-dependent)
**Layer**: Frontend visualization component
**CVSS**: 3.7 (AV:N/AC:H/PR:N/UI:N/S:U/C:L/I:N/A:N)
*(Score reflects that exploitation requires a consumer to misuse this for a security purpose, which is not the library's intent. Rated Low rather than None because the pattern is present and could be copied into security-sensitive extensions.)*

**Evidence**:
```ts
// src/viz/force-graph.tsx:83–84
x: width / 2 + (Math.random() - 0.5) * width * 0.6,
y: height / 2 + (Math.random() - 0.5) * height * 0.6,
```

**Context**: `Math.random()` is used here to spread nodes across the canvas before the force simulation runs. This is a legitimate cosmetic use — reproducibility of layout is not a security requirement, and no security token, session ID, or secret is derived from this value.

**Risk**: The risk to *this library* is negligible. The risk is that developers consuming VizBox may see `Math.random()` used in this file and, when extending the ForceGraph or adding node ID generation, replicate the pattern for something that *does* require unpredictability (e.g., generating unique node IDs that must not be guessable). In that context, a predictable value could be exploited.

**Recommendation**: Add a JSDoc comment making the non-security intent explicit, and provide an alternative for consumers who need unpredictable IDs:

```ts
// src/viz/force-graph.tsx:79–87
const initialNodes: Node[] = nodeRows.map((r) => ({
  id: String(r[idField] ?? r['id'] ?? ''),
  label: String(r[labelField] ?? r['label'] ?? ''),
  group: r['group'] !== undefined ? String(r['group']) : undefined,
  // Math.random() is intentional here: used only for visual initial placement,
  // not for security-sensitive ID generation. If you need unpredictable IDs,
  // use crypto.randomUUID() or crypto.getRandomValues() instead.
  x: width / 2 + (Math.random() - 0.5) * width * 0.6,
  y: height / 2 + (Math.random() - 0.5) * height * 0.6,
  vx: 0,
  vy: 0,
}));
```

**CVSS Breakdown**: AV:N (network-accessible component) / AC:H (requires misuse by a consumer) / PR:N / UI:N / S:U / C:L (layout predictability leaks positional info only) / I:N / A:N
