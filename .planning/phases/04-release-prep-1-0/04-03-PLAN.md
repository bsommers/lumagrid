<objective>
Define the plugin registry semantics (D-05, D-06, D-07), fix the groupBy type before the freeze (D-15), and tag the registry and transform layers for the API report (D-08, D-10).

Purpose: duplicate ids silently overwrote earlier plugins, `registerPlugin` returned nothing, and `groupBy.transform(...)` did not typecheck; each is cheaper to fix before 1.0 than after.
Output: updated registry module and tests, corrected groupBy type, `@public` tags on 21+ registry/transform exports, `PipelineStep` exported.

Decision recorded for D-15 (planner's choice): fix the type to the factory signature (option 1). A plain options-driven groupBy like pivot would be a silent no-op inside `TransformPipeline` (pipeline.ts: `TransformPipeline.run` never passes per-step options) and every README and TSDoc example calls `groupBy('category')`; option 2 would break those or need a hybrid callable object. The shapes remain different by design (aggregate, pivot, geoNormalize are pre-configured objects called as `transform(data, options)`; groupBy is a factory) and are documented in the `ChainableTransform` TSDoc.
</objective>
