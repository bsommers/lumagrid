<decisions_made>

- **Identity adapters for native charts**: `createNativePlugin` uses `dataAdapter: (d) => d` and `themeAdapter: (t) => t` — native charts accept `TransformedData` and `ThemeDefinition` directly, no reshaping needed
- **`theme` as explicit prop on viz components**: Removed `useTheme()` from all 7 chart components so they are pure functions of their props. Theme still flows via `ThemeProvider` context to `ViewSwitcher`, which extracts it and passes it through the plugin's `themeAdapter`.
- **`TreeNodeRow` gets `theme` prop**: The internal `TreeNodeRow` sub-component in `tree-view.tsx` also called `useTheme()`. Threaded `theme` down as a prop instead.
- **`[key: string]: unknown` index on `NativeChartProps`**: Allows `PieChartProps`, `ChoroplethProps`, `TreeViewProps` to extend it with typed extra fields while still letting `NativeRenderer` spread `config` onto the component safely.
- **`createD3Visualization` shim kept (deprecated)**: Old API still works for any consumer who already wrote a `D3ChartLifecycle`. It internally calls `createD3Plugin`. Marked `@deprecated`.
- **`D3Theme` extracts from `ThemeDefinition` automatically**: `toD3Theme()` is built into `createD3Plugin`. Consumers never need to write a `themeAdapter` for D3 charts.
- **`RechartsConfig` uses auto-detection**: `defaultDataAdapter` infers `nameKey`/`dataKey` from `data.fields` metadata when not explicitly configured.
- **ResizeObserver only activates when width/height are CSS strings**: If both are numbers, the observer is skipped. This avoids unnecessary DOM observation overhead on fixed-size widgets.
</decisions_made>

The key architectural insight: `ViewSwitcher` is now a pure dispatcher — it knows nothing about
chart internals. It only calls three methods: `dataAdapter`, `themeAdapter`, and renders
`<plugin.Renderer>`. Adding a new chart library (Nivo, Victory, ECharts) requires only:
1. Writing an adapter file (like `recharts-adapter.ts`)
2. Calling `registerPlugin(createXPlugin({...}))` once at app startup

The `WidgetContainer` is now fully responsive — pass `width="100%"` and the container
measures itself via `ResizeObserver`, passing pixel dimensions down to children.
